# Ternary Bonsai 2 27B (PQ2_0) — портативный лаунчер

> **Только для Intel Arc B580.**
>
> Все пресеты, все флаги и все цифры ниже замерены на **Intel Arc B580
> (12 ГБ VRAM)** с **Vulkan**-сборкой форка PrismML llama.cpp на Windows.
>
> Вся настройка сводится к одному правилу: веса модели 6540 MiB должны
> влезать в VRAM вместе с KV-кэшем, которому остаётся около 4 ГБ. Отсюда
> выбирается `f16`, `q8_0` или `q4_0` для конкретного контекста. На
> видеокарте с другим объёмом VRAM кэш не сходится, уходит в системную
> память, и decode падает в 5-8 раз. Пресеты запустятся, но с другими
> скоростями.
>
> Другим видеокартам: берите подходящую сборку движка (CUDA / Metal) из
> [релизов PrismML](https://github.com/PrismML-Eng/llama.cpp/releases) и
> пересчитывайте таблицу контекстов под своё железо.

Запускает [`OS-Software/Ternary-Bonsai-2-27B-Uncensored-Heretic-GGUF`](https://huggingface.co/OS-Software/Ternary-Bonsai-2-27B-Uncensored-Heretic-GGUF) — 27B тернарную модель рассуждений на 7,2 ГБ — через OpenAI-совместимый сервер. Пресеты контекста от 32k до 262k токенов, все замерены.

Один файл делает всё: качает движок, качает модель, поднимает сервер.

---

## Почему это нельзя просто открыть в LM Studio

Модель хранит веса в формате **ggml type 142 (`PQ2_0`)**. Любой стоковый llama.cpp её отвергает:

```
gguf_init_from_reader: tensor 'output.weight' has invalid ggml type 142. should be in [0, 43)
```

Обновление LM Studio, смена runtime, переименование файла в `Q2_0` — ничего не поможет. `Q2_0` загрузится без ошибки и начнёт выдавать мусор, потому что у него нет Hadamard-активации на исполнении.

Работает только **[форк PrismML llama.cpp](https://github.com/PrismML-Eng/llama.cpp)** с тернарными ядрами. Лаунчер скачивает его сам.

## Быстрый старт

```bat
bonsai.bat
```

| Клавиша | Действие |
| --- | --- |
| `1` | скачать движок (форк PrismML llama.cpp) |
| `2` | скачать модель (7,2 ГБ, с докачкой) |
| `3` | скачать зрительную башню (0,93 ГБ, только для картинок) |
| `4`–`9` | запустить протестированную конфигурацию |
| `S` | порт / потоки / слоты / свой контекст |
| `T` | проверить работающий сервер |

Меню показывает, что уже скачано (`INSTALLED` / `not installed`) и какие значения сервера действуют сейчас.

Можно без меню:

```bat
bonsai.bat 65k-q8_0
```

Имена: `32k-f16`, `32k-q8_0`, `65k-f16`, `65k-q8_0`, `131k-q8_0`, `262k-q4_0`.

API совместим с OpenAI:

```
Base URL : http://127.0.0.1:18098/v1
API key  : любой текст
Model    : любой текст (например "local")
```

## Протестированные конфигурации

Замеры: Ryzen 5 5500 (6C/12T) + Intel Arc B580 (12 ГБ VRAM), 32 ГБ RAM, `-ngl 99 -fa on -t 12 -np 1`, промпт 2152 токена.

| Пресет | Контекст | KV cache | decode | prompt eval | VRAM | Примечание |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| `32k-f16` | 32 768 | f16 | **24,9 tok/s** | 415 tok/s | 8,81 ГБ | лучшее качество |
| `32k-q8_0` | 32 768 | q8_0 | 24,6 tok/s | 414 tok/s | 7,87 ГБ | |
| `65k-f16` | 65 536 | f16 | 24,4 tok/s | 415 tok/s | 10,84 ГБ | VRAM впритык, см. ниже |
| `65k-q8_0` | 65 536 | q8_0 | 24,3 tok/s | 388 tok/s | 8,96 ГБ | **рекомендую** |
| `131k-q8_0` | 131 072 | q8_0 | 23,8 tok/s | 397 tok/s | 11,16 ГБ | |
| `262k-q4_0` | 262 144 | q4_0 | 24,3 tok/s | 219 tok/s | 10,68 ГБ | максимум контекста, качество KV ниже |

Скорость генерации почти одинаковая во всём диапазоне — 24 tok/s на 32k и на 262k. Падает только prompt eval на максимальном контексте.

### Правило, которое решает всё

Веса модели занимают **6540 MiB**. Видеокарта отдаёт около **11199 MiB** свободных. Значит KV-кэш должен влезать в оставшиеся ~4 ГБ, иначе он уходит в системную память и decode падает в 5-8 раз.

| Тип KV | 32 768 | 65 536 | 131 072 | 196 608 | 262 144 |
| --- | ---: | ---: | ---: | ---: | ---: |
| f16 | 2048 MiB | 4096 MiB | 8192 MiB | 12288 MiB | 16384 MiB |
| q8_0 | 1024 MiB | 2048 MiB | 4096 MiB | 6144 MiB | 8704 MiB |
| q4_0 | 512 MiB | 1024 MiB | 2048 MiB | 3264 MiB | 4352 MiB |

`262k-q4_0` дополнительно передаёт `-b 512 -ub 128` — это уменьшает compute-буфер с ~390 до ~150 MiB и в конечном счёте позволяет всё влезть.

### Не используйте `-nkvo`

Перенос KV-кэша в системную память через `--no-kv-offload` стоит **8-кратной потери decode** (22 → 2,6 tok/s). Замерено.

### 65k f16 — самый ненадёжный

Оставляет всего ~0,4 ГБ запаса по VRAM. Как только что-то ещё занимает видеопамять, он уходит в пролив и падает с 24 до **4 tok/s**. Именно так выглядит «модель выдаёт по одному токену в секунду». Берите `65k-q8_0`.

## Что выбрать

| Задача | Конфиг |
| --- | --- |
| лучшее качество, обычный чат | `32k-f16` |
| повседневная работа | `65k-q8_0` |
| длинные документы | `131k-q8_0` |
| максимум контекста | `262k-q4_0` |

Потери качества: KV `q8_0` — мягкая, `q4_0` — заметная. `262k-q4_0` существует лишь потому, что под f16 понадобилось бы 16 ГБ VRAM.

## Проверка контекста

`verify-context.ps1` прогоняет тест «игла в стоге сена»: прячет уникальный код на ~50% глубины длинного промпта и спрашивает его в конце. Значение `n_ctx` из `/props` доказывает только то, что окно выделено, но не то, что модель может им пользоваться.

```powershell
powershell -ExecutionPolicy Bypass -File verify-context.ps1 -TargetTokens 60000
```

## Важные детали

- Это **thinking-модель**. Она рассуждает перед ответом, поэтому нужен большой лимит токенов. При `max_tokens` в пару сотен она израсходует всё на размышление и вернёт пустой ответ. Ставьте 8 000–16 000.
- Сборки движка рассчитаны на **Windows + Vulkan** (Intel Arc). Сборки под CUDA и Metal есть в релизах PrismML — поменяйте `ENGINE_TAG` и имя архива в `bonsai.bat`.
- Модель под лицензией Apache 2.0, без цензуры — отвечает на то, что спрашивают.
